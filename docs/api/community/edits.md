# 作者修改食记

`PUT /api/v1/community/posts/{id}`，当前正常会话、CSRF 与现有参与策略校验；只能修改本人未删除的帖子，管理员不能借此修改他人帖子。

```json
{
  "expectedRevision": 1,
  "clientRequestId": "6bfde29d-874b-457e-bf52-147461618032",
  "title": "更正后的标题",
  "content": "更正后的正文",
  "imageUrls": ["/api/v1/media/681fb2a1-197e-46c8-b1bc-c911fd0978be"],
  "dishId": null
}
```

完整替换四个可编辑字段。标题 1–50、正文 1–2000；原创保留 1–9 张图片，转发允许 0–9 张；图片不得重复，均须本人上传。`dishId: null` 清除关联，非空关联须为当前启用菜品。转发来源、作者、ID 和原发布时间不可改。

200 返回 `{id, revision, changed}`。相同内容为不变更操作，`changed: false`，不隐藏已公开帖子、不增加版本或消耗投稿额度。真实修改复用投稿限流，原状态无论公开／待审／被拒，均产生新版本并回到现有 AI／人工待审流程。旧正文及审核结果存入内部快照；点赞、评论、收藏、浏览量、原时间与关系不重建。详情、流和审核队列增加 `contentRevision`；详情及流增加 `editedAt`，未修改时为空。

`POST_EDIT_CONFLICT`（409）表示所见版本已过期，应保留输入并由用户明确读取最新版本，不能自动重放覆盖。`REQUEST_CONFLICT`（409）表示同一请求编号已用于不同载荷。同一请求编号和载荷重试返回第一次结果，即使之后又有更新也不重复写入。原始创建请求单独保存，不因作者编辑而破坏创建重试。

人工审核 `POST /api/v1/admin/community/posts/{id}` 必须携带所见 `contentRevision`；新版本不符返回 `POST_REVIEW_CONFLICT`。尚未修改的版本 1 保留原请求形式；版本 2 起不允许缺省版本。AI 网络诊断不持有帖子锁；落库、逐图诊断结果和最终决定均核对原版本并锁定，旧结果直接丢弃。评论审核不携带帖子内容版本。

V57 新增版本／修改请求表、原始创建载荷、修改时间、转发计数标记与审核日志快照。正式部署先升级后端，再更新客户端；不得改写旧迁移。旧审核日志和移除图片的内部证据保留，文件清理会检查版本引用；不提供公开修改历史。转发审核首次通过才增加原帖转发数，编辑再通过不重复增加。

置顶由独立[置顶契约](pins.md)管理。修改待审／被拒期间保留置顶名额与顺序但不公开，重新通过自动恢复；删除／下架取消置顶。
