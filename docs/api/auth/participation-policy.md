# 普通账号参与权限策略

`app.participation.school-email-required`，环境变量 `PARTICIPATION_SCHOOL_EMAIL_REQUIRED`，默认 `false`。

- `false`：已登录、启用的非学校邮箱账号与学校邮箱普通账号使用相同权限和额度。包括发帖、评论、点赞、收藏、关注、私信、投稿、纠错提交和每天 5 条反馈；内容审核、所有权、各业务限流、单设备每天 10 条反馈等规则继续生效。
- `true`：恢复原学校邮箱门槛，数据库 `visitor` 使用原只读白名单与每天 2 条反馈；已绑定的普通账号不受影响。

修改配置后重启后端。每个有效会话请求重新读取身份并解析策略，不需要批量改角色、迁移数据库或让用户重新注册。客户端刷新会话／重新进入后同步界面；旧界面仍不能绕过后端限制。

`ParticipationPolicy` 是唯一的普通参与权限映射入口：只把启用账号的存储角色 `visitor` 投影成有效角色 `user`。注册响应、登录、会话校验和本人资料保持一致；`/users/me/capabilities` 由相同有效身份生成。存储角色、学校邮箱和认证时间不因此变化。`role=user` 不等于学校邮箱已认证，认证必须检查 `schoolEmailVerified`。管理端目标角色仍读取数据库，不能把权限投影回写到目标账号。

学校邮箱绑定、解绑、验证码、1 小时冷却、管理员／超管禁止绑定解绑等规则保持不变。解绑后存储身份恢复 `visitor`；开放策略下有效权限仍为普通用户，恢复门槛后按存储身份限制。学校邮箱认证不会被伪造或自动补齐。

匿名、已停用、已注销账号不获得新权限，受限申诉会话仍只能访问原允许路径；普通账号不获得任何管理员或超管能力。注册邮箱白名单、邀请码／开放／关闭注册模式和注册限流与此策略独立。

测试：`ParticipationPolicyTest`、`ParticipationConfigurationTest`、现有会话切换策略用例；`OpenParticipationIT` 验证开放模式的真实 HTTP／会话／SMTP／数据库链路。既有集成用例明确采用 `school-email-required=true`，继续覆盖恢复门槛时的写限制、额度、绑定解绑和所有权，不删除旧限制断言。
